First run

Install first: clone the repo and symlink skills/voxer-ticketsmith into ~/.claude/skills, or add it as a plugin. The README has both commands.

C

Home page

Home
  • Needs youitems with a draft or a question, newest first
  • New, not sorted yettickets that appeared since the last sync; file each as Todo or Backlog
  • Ready for reviewa branch to look at, or In Review in Linear
  • ActiveIn progress, Blocked, Todo
  • Everything elseTriage and Backlog, collapsed
  • Done recentlyclosed in the last 30 days, collapsed; pages and threads stay

The lead sentence at the top is the whole status. Each row opens the ticket page; the small Linear link opens Linear. The Todo, Backlog and Tonight buttons change this page only, never Linear.

Tonight marks a ticket approved for your own evening commands; this skill never reads it.

Ticket page

Ticket page
  • A Where things standsub-issues done, next action
  • B Goalone line from the Linear description
  • C.. Howdiagrams and lists from the ticket's tasks file
  • Sub-issuesone line each, colour says done, started, blocked
  • Needs youdrafts to edit, questions to answer
  • Threadtell the agent what to change

Only the goal and the sub-issue list come from Linear. The rest lives in ~/.voxer-ticketsmith/.

E

Act on an item

Post is the only thing that writes to Linear. Slack and Voxer replies are copy-only; you send them yourself.

F

Talk to the agent

Write a plain request in the Thread box and click Send now:

  • shorten this draft
  • draft a reply to Ben
  • draft a sub-issue for the retry case
  • add the decision we made in standup
  • redraw the flow with the new queue

The answer lands in the thread and the page updates. Nothing reaches Linear from the thread.

By tool

You have What changes
Linear only ✓items come from comments on your tickets; paste a message into the thread to get a draft
Slack ✓set inputs = ["slack"] and slack_channels in config.toml; relevant DMs and mentions become items
Voxer ✓add "voxer" to inputs; it skips untranscribed audio
Notion ✓nothing to set; pages are read when a ticket links to them
Your own automation ✓a [[commands]] entry in config.toml routes a thread keyword to your skill
H

Make it yours

config.toml
interval_min, model, port, inputs, slack_channels, product_teams
style.md
how drafts should sound; its Never write list feeds the checker
tasks/<ticket>.md
the how, as diagrams; the agent keeps it current
your own worker
a [[commands]] entry runs your skill on "work on this"; it reads state.json, tasks and threads, and writes a work item back

Both files are optional and live in ~/.voxer-ticketsmith/. The README section Bring your own worker has the full contract and a cron line for a nightly run over the tickets you marked Tonight.
